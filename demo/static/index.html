วิธีทำงาน

ทุกปุ่มในแอปเรียกโค้ดจริงของโปรเจกต์ (src/svdmark) และทำงานบนเครื่องนี้ทั้งหมด รูปไม่ถูกส่งไปไหน

ซ่อนข้อความ (QIM บน σ₁ ของแต่ละบล็อก)

  1. แปลงรูปเป็นภาพเทา แล้วแบ่งเป็นบล็อก b×b (Balanced = 8×8) แต่ละบล็อกเก็บได้ 1 บิต
  2. ทำ SVD ของบล็อก A = UΣVᵀ แล้วดูค่า σ₁ (singular value ตัวใหญ่สุด ≈ b × ความสว่างเฉลี่ยของบล็อก)
  3. แบ่งแกน σ เป็นช่องกว้าง Δ ช่องเลขคู่ = บิต 0 ช่องเลขคี่ = บิต 1 แล้วย้าย σ₁ ไปกลางช่องที่ตรงกับบิตที่ต้องการ σ₁ จึงเพี้ยนได้ ±Δ/2 โดยยังอ่านบิตเดิมได้
  4. สร้างบล็อกกลับ ปัดเป็นจำนวนเต็ม 0–255 แล้วอ่านซ้ำทันที (closed-loop) ต้องได้บิตถูกและห่างขอบช่องอย่างน้อย Δ/4
  5. ข้อความเก็บเป็น 16 บิตความยาว + CRC-16 + เนื้อความ UTF-8 ผู้รับใช้ CRC ตรวจว่าข้อความครบ (ok / damaged / no_message)
  6. Key (ถ้าใส่) ผ่าน PBKDF2-HMAC-SHA256 แล้วเลื่อนเส้นแบ่งช่องของแต่ละบล็อกไปคนละระยะ คนที่ไม่มี key จึงอ่านไม่ได้
  7. Hamming(7,4) ECC (ถ้าเปิด) คูณข้อมูล 4 บิตด้วยเมทริกซ์ G (mod 2) ได้ 7 บิต ผู้รับคำนวณ syndrome s = Hr แล้วแก้บิตผิดได้ 1 บิตต่อกลุ่ม

Watermark (Liu & Tan, 2002)

  1. SVD ของทั้งรูป A = UΣVᵀ แล้วบวกโลโก้ W เข้าไป: D = Σ + αW
  2. SVD ของ D = UwΣwVwᵀ แล้วสร้างรูปใหม่ Aw = UΣwVᵀ
  3. ตอนตรวจ หา Σ* ของรูปที่ได้รับ แล้วดึงโลโก้ W* = (UwΣ*Vwᵀ − Σ)/α และวัด NCC กับโลโก้จริง
  4. ปัญหา: key (Uw, Vw) จำหน้าตาโลโก้ไว้เกือบทั้งหมด รูปที่ไม่เคยฝังก็ได้ NCC สูง เราจึงเพิ่ม shift score = cos(σ* − σ, σw − σ) ซึ่งเป็น 0 สำหรับรูปที่ไม่เคยฝัง

ข้อจำกัดที่วัดได้จริง

  • Machine learning detector อย่างง่ายจับรูปที่ซ่อนข้อความเต็มความจุได้ (AUC ≈ 0.99) แม้ใส่ key เพราะเกิดรอยที่ขอบบล็อก
  • Rotate 0.5° ทำให้ข้อความหายทุก mode เพราะตารางบล็อกเลื่อน ส่วน watermark ทนการหมุนเล็กน้อยได้
  • Blur ทำให้ shift score ติดลบทั้งรูปที่ฝังและไม่เคยฝัง เกณฑ์ 0.8 / 0.3 ในแอปจึงใช้ตัดสินไม่ได้หลังเบลอ
