เดโม SVD: ซ่อนข้อความลับ และฝังลายน้ำในภาพ

ทุกปุ่มเรียกโค้ดจริงของโปรเจกต์ (src/svdmark) · ทำงานบนเครื่องนี้ทั้งหมด รูปไม่ถูกส่งไปที่ไหน

1เลือกรูป

กดรูปตัวอย่าง หรืออัปโหลดรูปของคุณเอง (รูปจะถูกแปลงเป็นขาวดำ และถ้าใหญ่เกิน 640 พิกเซลจะถูกย่อ)

ไม่พบรูปตัวอย่าง (ยังไม่ได้วางชุด BSDS500 ใน data/images) อัปโหลดรูปเองได้เลย

2ฝั่งผู้ส่ง: ซ่อนข้อความ

ข้อความภาษาไทยใช้ 3 ไบต์ต่อตัวอักษร ภาษาอังกฤษ/ตัวเลข 1 ไบต์

เลือกรูปก่อน

ทุกโหมดคุณภาพภาพเท่ากัน (Δ = 4b → PSNR ≈ 40.8 dB เมื่อใช้เต็มความจุ) ต่างกันที่ความจุกับความทน

ส่งรูปให้เพื่อนเป็นไฟล์ PNG เท่านั้น ถ้าส่งผ่าน LINE / Facebook / ถ่ายหน้าจอ รูปจะถูกบีบอัดเป็น JPEG และข้อความอาจเสีย (ลองดูในขั้นที่ 4)

3ฝั่งผู้รับ: อ่านข้อความ

ผู้รับต้องรู้ "รหัสลับ" และ "โหมด" เดียวกับผู้ส่ง

4ลองโจมตีดู: ข้อความรอดไหม?

เอารูปที่ซ่อนในขั้นที่ 2 มาทำให้เสียหาย แล้วอ่านด้วยรหัสและโหมดเดิม ระบบนับให้ด้วยว่าบิตของข้อความผิดกี่บิต

1เลือกรูป

ใช้รูปเดียวกับแท็บซ่อนข้อความได้

2ฝังลายน้ำ (วิธีของ Liu & Tan, 2002)

ลายน้ำคือภาพขาวดำขนาดเท่าด้านสั้นของรูป (เช่น 320×320) บวกเข้าไปในค่า σ ของทั้งรูป

หรืออัปโหลดรูปโลโก้:

α มาก = ลายน้ำทนกว่า แต่ภาพเสียมากขึ้น · ผลทดลองของเรา: α = 16 ยังได้ PSNR ≥ 40 dB กับโลโก้แบบนี้

3ถอดลายน้ำ และตรวจว่าเชื่อได้ไหม

การถอดต้องใช้ "key" ที่เก็บไว้ตอนฝัง (U, V, S, Uw, Vw, α) แอปจำ key ไว้ให้จนกว่าจะปิดแอป

ทำไมรูปที่ไม่เคยฝังก็ถอดโลโก้ออกมาได้?

ตอนฝัง เราคำนวณ SVD ของ D = Σ + αW ได้ Uw, Σw, Vw แล้วเก็บ Uw, Vw ไว้ใน key ส่วนของ W ที่อยู่ นอกเส้นทแยง ถูกเก็บเป็น "มุมเอียงเล็กๆ" ของ Uw, Vw ซึ่งอยู่ใน key ไม่ใช่ในรูป มีแค่ส่วน บนเส้นทแยง (320 จาก 102,400 ช่อง) ที่ไปเปลี่ยนค่า σ ของรูปจริงๆ ดังนั้นใครถือ key ก็ถอดโลโก้ได้เกือบทั้งหมดจากรูปไหนก็ได้ที่ σ ใกล้กับต้นฉบับ สังเกต เส้นทแยงมืด ในโลโก้ที่ถอดจากต้นฉบับ: นั่นคือส่วนที่หายไปเพราะ σ ไม่ได้ขยับจริง

เราจึงเสนอ shift score = cos(σ ของรูปที่ตรวจ − S, Sw − S) ถามว่า "σ ของรูปนี้ขยับไปทางเดียวกับที่การฝังทำหรือเปล่า" รูปที่ฝังจริงได้ ≈ 1 รูปต้นฉบับได้ 0 เกณฑ์ 0.8 / 0.3 ที่แอปใช้เป็นค่าคร่าวๆ จากผลทดลอง ไม่ใช่ค่ามาตรฐาน

บันทึกการทดสอบกับเพื่อน

ให้เพื่อนลองตามแต่ละกรณี แล้วบันทึกสิ่งที่เห็น ผลถูกเก็บในไฟล์ demo/demo_log.csv (เปิดด้วย Excel ได้) เป้าหมาย: เพื่อนอย่างน้อย 2 คน ลองอย่างน้อย 10 กรณี

ผลที่บันทึกล่าสุด

ซ่อนข้อความทำงานยังไง (สรุปสั้น)

  1. แบ่งรูปเป็นบล็อก b×b (เช่น 8×8) แต่ละบล็อกซ่อนได้ 1 บิต
  2. ทำ SVD ของบล็อก A = UΣVᵀ แล้วดู σ₁ (ค่า singular value ตัวใหญ่สุด ≈ b × ความสว่างเฉลี่ยของบล็อก)
  3. แบ่งแกน σ เป็นช่วงกว้าง Δ ช่วงเลขคู่ = บิต 0 ช่วงเลขคี่ = บิต 1 แล้วย้าย σ₁ ไปกลางช่วงที่ตรงกับบิตที่ต้องการ
  4. สร้างบล็อกกลับ ปัดเป็นจำนวนเต็ม 0–255 แล้ว อ่านซ้ำทันที (closed-loop) ต้องอ่านได้บิตถูกและอยู่ห่างขอบช่วงอย่างน้อย Δ/4 ไม่งั้นลองช่วงถัดไป
  5. ข้อความถูกแปลงเป็นบิต: ความยาว 16 บิต + CRC 16 บิต + เนื้อความ (UTF-8) ผู้รับใช้ CRC ตรวจว่าข้อความครบถูกต้อง
  6. รหัสลับ (ถ้าใส่) เลื่อนเส้นแบ่งช่วงของแต่ละบล็อกไปคนละระยะแบบสุ่ม คนที่ไม่มีรหัสจึงอ่านไม่ได้ ระยะเลื่อนสร้างจากรหัสผ่าน PBKDF2-HMAC-SHA256 (200,000 รอบ) ทำให้การเดารหัสแต่ละครั้งช้า (ราว 0.07 วินาที) รุ่นแรกใช้ CRC32 ซึ่งมีแค่ 2³² แบบ ลองครบได้ในราว 1 วัน · ไม่ใช่การเข้ารหัส และรหัสสั้นหรือเป็นคำทั่วไปยังเดาได้
  7. แก้บิตผิดอัตโนมัติ (ถ้าเปิด) ใช้รหัส Hamming(7,4): ข้อมูล 4 บิต d คูณเมทริกซ์ G (mod 2) ได้ 7 บิต ผู้รับคำนวณ s = H·r (mod 2) ถ้า s ไม่เป็นศูนย์ s จะตรงกับคอลัมน์หนึ่งของ H ซึ่งบอกตำแหน่งบิตที่ผิด แล้วพลิกกลับ

ข้อจำกัดที่วัดได้จริง

  • ตัวตรวจจับที่ฝึกด้วย machine learning ง่ายๆ จับรูปที่ซ่อนข้อความเต็มความจุได้ AUC ≈ 0.99 แม้ใส่รหัสลับ เพราะการเปลี่ยน σ₁ = บวก d·u₁v₁ᵀ ซึ่งเกือบเป็นการเลื่อนความสว่างทั้งบล็อกเท่ากัน จึงเกิด "ขั้น" เล็กๆ ที่ขอบบล็อก (ข้อความสั้น AUC ≈ 0.79)
  • หมุนรูปเพียง 0.5° ข้อความหายทุกโหมด เพราะตารางบล็อกเลื่อน ส่วนลายน้ำทนการหมุนเล็กน้อยได้ แต่ไม่ทนการเบลอ
